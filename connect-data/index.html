Connect Lab Notebook data with Inventory items

This tutorial shows division members how to connect research data registered in the Lab Notebook with related Inventory objects in the Data Store. Using the synthetic “Material Synthesis” example, you will connect Experimental Steps with instruments, chemicals, samples, and other Experimental Steps using parent-child relationships so that the origin and processing history of research datasets can be traced.

Before you begin

This tutorial is designed for openBIS version 20.10.12 and requires prior experience with openBIS. It builds directly on the earlier Lab Notebook and Inventory tutorials. Before starting, you should already be comfortable navigating Projects, Collections, Objects, and Datasets and editing registered objects and their metadata.

Before starting this tutorial, you must:

  • Read the guideline “How to represent research data in the Data Store” and understand the recommended structure Space → Project → Collection → Object → Dataset.
  • Complete “Upload data in the Lab Notebook”. Your User Space should contain the Material Synthesis Project, the tutorial Collections, Experimental Steps, and the datasets attached to the corresponding Experimental Steps.
  • Complete “Register inventory items”. The required Instrument and Chemical objects should be available and the Sample objects for the tutorial should already be registered in the Inventory.
  • Have the user role to edit the relevant FB Inventory objects.
  • Have access to the playground instance (access restricted to BAM employees with VPN connection). How to log in to the Data Store instances is described in this guide.
  • If you encounter problems, contact the Data Store team.
Do not continue with an incomplete tutorial structure: this tutorial updates objects that already exist. If Experimental Steps, Instruments, Chemicals, or Samples from the previous tutorials are missing, register them first rather than creating substitutes during the connection exercises.

Key concepts

Parent-child relationships

Objects represented in openBIS can be connected using parent-child relationships. For research-data traceability, these relationships can link Experimental Steps in the Lab Notebook with the resources used during an activity and with the outputs generated by that activity. Datasets remain attached to the Experimental Step that describes how they were generated.

openBIS parent-child relationships describe a directed connection between registered openBIS Objects. The terms parent and child therefore do not have the same meaning as in programming languages, where they often describe inheritance, class hierarchies, or ownership in a software structure. In openBIS, they are links used to represent how research Objects are related. Decide which Object is the parent and which is the child before saving or batch-updating a relationship. A useful convention for this tutorial is to represent resources and inputs as parents of an Experimental Step, and generated Samples or downstream Experimental Steps as its children.

Parent-child hierarchy graph generated in openBIS

Once parent-child connections have been assigned between Objects, openBIS can visualise them as a Hierarchy Graph. The graph is the openBIS representation of the directed connections that were first shown conceptually as unidirectional arrows in the “Material Synthesis” data model. Each node in the graph is an openBIS Object, and each connection corresponds to an Object-to-Object parent-child relationship.

For example, the Synthesis Instrument and the Chemicals Chemical 1 and Chemical 2 appear upstream of the Material Synthesis Experimental Step, while the generated Synthesized Material Sample appears downstream. If that Sample is later used in another Experimental Step, the graph can continue through that downstream activity and show a larger part of the research workflow.

What the graph contains: The Hierarchy Graph visualises only parent-child relationships between Objects. Datasets are not displayed as nodes. A dataset remains attached to the Experimental Step that describes how it was generated. To understand a dataset in context, open its Experimental Step and inspect the Object hierarchy around that step.

Traceability through connected objects

The value of these connections becomes clear when researchers need to reconstruct what happened to a Sample or understand how a dataset was generated. The following use cases show how the same relationship network supports traceability in practice.

Use case 1: What was done with a Sample, and who generated it?

Imagine that several division members have registered Samples with the same descriptive name, Synthesized Material. A researcher first identifies the correct Sample in the Samples Collection by using metadata such as the Co-responsible person. This property helps distinguish who registered and shares responsibility for that Sample.

After opening the correct Sample Object, the researcher can follow its parent-child connections. The upstream connection points back to the Material Synthesis Experimental Step that generated it. From that Experimental Step, the researcher can continue upstream to see which resources were involved—for example the Synthesis Instrument and the Chemicals Chemical 1 and Chemical 2. If the Sample was later used in another Experimental Step, its downstream connection shows what was subsequently done with it.

In this way, the Sample Object becomes an entry point for answering practical questions such as: Who was responsible for this Sample? Which experiment generated it? Which resources were used? Was the Sample used again later, and in which activity?

Use case 2: How was this dataset generated, and can the process be reproduced?

Now imagine that a researcher finds a dataset in the Lab Notebook and wants to understand how it was produced. The dataset itself is not part of the parent-child hierarchy. Instead, it is attached to the Experimental Step that describes the activity through which the data were generated. The researcher therefore starts with that Experimental Step and follows its connected Objects.

For the Material Synthesis dataset, the researcher can identify the Instrument and Chemicals connected as parents and the generated Sample connected as a child. The Experimental Step metadata, its attached dataset, and the connected Inventory Objects together provide the context needed to understand how the data were produced.

This connected context can support reproducibility by helping another researcher identify the same kinds of inputs, resources, and outputs; it can support standardization by making it easier to compare whether repeated experiments follow the same documented workflow; and it can support other downstream processes such as review, quality assurance, reuse, or preparation of research outputs.

Traceability principle: Use datasets to identify the Experimental Step that generated the data, and use parent-child connections between Objects to reconstruct the surrounding research workflow. Use Sample metadata such as Co-responsible person to identify the correct physical or material output before tracing its upstream and downstream connections.

From research workflow to openBIS object relationships

In the “Material Synthesis” example, the logical connections drawn in the research workflow are the relationships that will later be implemented in openBIS. The direction of each arrow helps decide which Object is the parent and which is the child. For example, an Instrument or input Sample can point toward the Experimental Step in which it is used, while an Experimental Step can point toward the Sample it generates.

After these relationships have been registered, openBIS can visualise the resulting Object genealogy as a Hierarchy Graph. This provides a direct implementation view of the same research logic shown in the research workflow below: the conceptual arrows become stored parent-child connections, and the graph lets users inspect how Experimental Steps, Samples, Instruments, Chemicals, and other Objects are connected.
