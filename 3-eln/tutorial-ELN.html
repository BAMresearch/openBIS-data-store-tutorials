Key concepts

Logical research workflow

Before uploading data, document in the Lab Notebook (ELN) the experimental steps that describe how each dataset was generated. A useful way to begin is by drawing a flow diagram that represents the logical structure of the research project.

In this workflow, the experimental steps are represented as the “things you do” (yellow boxes), while the research data is represented as datasets attached to those experimental steps (red boxes).

Note:

openBIS and Data Store core Data Model

This tutorial uses the classic openBIS data model, which consists of five hierarchically structured levels: Project / Collection / Object / Dataset. This helps explain the core logic of openBIS data model and demonstrates how objects, which are uniquely identified as entities, are connected to one anoter through parent-child relationships. The core openBIS data model is applied to three compartments of the Data Store (BAM Inventory, FB Inventory and ELN). In this tutorial, you will work with the Electronic Laboratory Notebook (ELN).

Starting with openBIS 20.10.12, the standard data model was expanded to support more flexible representations of complex research projects. You can explore the newer data model at [ADD LINK].

In this example, all experimental steps are represented as Objects. The project named 'Material Synthesis' comprises five collections ('Synthesis,Treatment non-destructive, Paremeter 1 and Parameter 2, Parameter 2 Analysis'), which contains the experimental steps done to generate the research data / Datasets.

Lab Notebook

In the Lab Notebook section, each user has a personal folder (Space in openBIS) for organizing research projects, experiments, simulations, and other activities that lead to the creation of datasets. Each of these activities can be represented as an experimental step. All steps should be connected. To do this, the steps are first registered in openBIS, and then parent-child relationships between them are defined. Experimental steps should also be linked to all elements used to carry them out, such as chemicals, instruments, and software. Datasets are attached to the corresponding experimental steps.

Step 1: Register a Project

Create a project in the ELN to represent the research project Material Synthesis.

Instructions for registering a Project:
  1. Click the upper LAB NOTEBOOK tab.
  2. Navigate to the Lab Notebook in the left-hand menu and open the drop-down menu to select Home Space.
  3. Click + Project to open the project form.
  4. Fill out Code and Description.
  5. Review the entries and click Save.

General information

This section provides guidance for completing the project form.

Code requirements
  • Mandatory fields in openBIS are marked with an asterisk (*).
  • Allowed characters: uppercase letters A-Z, digits 0-9, underscore (_), hyphen (-), and dot (.).
  • Separate words with underscores.
  • Codes should be meaningful, in English, and between 3 and 30 characters.
  • A code cannot be modified or reused.
Description requirements
  • Mandatory for BAM Data Store.
  • Should contain enough detail to be understandable to people outside the group.
  • Should follow the format: English//German.
  • Should contain 2 to 50 words.
Warning: If the Code field is not displayed and you encounter a white page, click the More drop-down menu and select Show Identification Info.
Warning: Once saved, the project code cannot be changed or reused within the same Space. To remove the project, select the project in the left-hand menu, open the More drop-down menu, and select Delete.

CONGRATULATIONS!!, you have created your first openBIS project.

Step 2: Register Collections of Experimental steps

A project can contain several collections to organize experimental steps, measurements, and other activities that generate research data. Collections are one way to logically structure experimental work.

Instructions for creating a collection:
  1. Navigate to the project you created in the left-hand menu.
  2. Click + Other.
  3. Select 'Collection' from the drop-down menu.
  4. Leave autogenerated Code(*)
  5. enter a meaningful Name. In this tutorial example [Name='Synthesis'].
  6. leave empty Default object type
  7. select 'List view' in Default collection view.
  8. Review the entries and click Save.

Step 3: Register Experimental steps

Any activity (Experiments, measurements, simulations, etc.) that generate research data can be represented in openBIS as Experimental Steps. This generic object type includes properties ('start date, Experimental goals, Description' etc.) to uniquely defined an Experimental Step. Custom properties can be set by users when defining Object types and controlled vocabularies ('openBIS Masterdata'). In this tutorial, we will use the pre-defined metadata for the generic object type 'Experimental Step' to understand the representation of experimental steps in the ELN.

Instructions for registering experimental steps:
  1. In the left-hand menu, navigate to the collection you want to use [collection name='Synthesis'].
  2. Open the drop-down menu More
    3. and select New Object.
  3. Click on 'Select an object type'.
  4. start typing the name of the object type. e.g., 'exp' or scroll down to select 'Experimental Step'.
  5. Fill out in the 'New Experimental Step' form, the properties displayed in the section 'Identification Info'.
  6. Fill out the [Name='Material Demo 001']
  7. Fill out all other relevant Properties
  8. Review the entries and click Save.

General information

This section provides guidance for completing the 'New Experimental Step' form.

  • The Code is mandatory (*) and is automatically generated by the system. It is not necessary to change it; however, if you do decide to do so, you must ensure consistency within your division and the Data Store.
  • The Name should be meaningful to you and your colleagues, as you will see it in the collections and search objects by Name.
  • The relevant information should be entered into the remaining fields/properties. Only properties marked with an asterisk (*) are mandatory and must be filled in so that the object can be saved.
  • Experimental steps can be edited after saving and will retain the same Code.
Warning:
  • If the Code field is not displayed and you encounter a white page, click the More drop-down menu and select Show Identification Info.

CONGRATULATIONS!!, you have created your first Experimental step named 'Material Demo 001'.

Step 4: Register Experimental steps using Templates

Experimental steps may require extensive information to describe the generated datasets. To standardize the information for experimental steps and faciliate the subsequent registration of similar experimental steps, templates can be created and saved for reused within the division. This is useful when Experimental steps are repetitive, some condiditions remain or require minor changes.

Instructions for registering Experimental Steps using Templates:
  1. In the left-hand menu, navigate to the collection you want to use [collection name = 'Synthesis'].
  2. Open the drop-down menu More
    3. and select New Object.
  3. Click on 'Select an object type'.
  4. Select 'Experimental Step'.
  5. Click on the Templates tab.
  6. Select the template [Template name = 'Material Synthesis']
  7. Leave the 'Merge current parents/children' option disabled
  8. Click Accept.
  9. Leave Code unchaged, enter the Name [Name= 'Material Demo1'].
  10. Enter the Start date and the End date using the calendar. Entering a time is not required, but possible.
  11. Scroll down to 'Comments' and enter a comment
  12. Review the entries and click Save.

General information

This section provides guidance for the use of Templates.

  • Templates must first be created for an object type, only then, you can select from the list of available templates for your division. Since templates are part of the ELN settings that all members of the group/division can see. Templates need to be created by a colleague in your division with 'Group Admin rights'; this role is typically assigned to Data Store Stewards (DSSt). If you are unsure who to contact, ask your division lead or contact the Data Store team.
Warning:
  • Once you register an Experimental step or any other object, it is not possible go back and select a template to edit it.
  • If the template you are using contains predefined (included none) parent-child relationships and you have already defined some parent-child relationships in your object that you wish to retain, you should enable the “Merge current parent-child relationships” option. This is needed, for example, when you register an object based on another object, which automatically creates a parent-child relationship. See Data Store Wiki article 'Register sequential Experimental Steps'

CONGRATULATIONS!!, You have deleted sucessfully an object (Experimental Step).

Warning:
    When deleting an object, you can delete other connected objects and attached datasets. If you do not want to do this and only want to remove the object, leave the option 'Delete also all descendant object(s) including their datasets' unckecked. Descendants are objects that you have linked to the object you want to delete. These can be parents objects (originated before) or children objects (originated after). A subsequent tutorial will explain more aboutopenBIS-parent-child relationships.

General information: Revert deletions. (This is not an excercise)

Deleted Objects are moved to the 'Trashcan' and can be reverted or deleted Permanently. To explore this function:

  • Click on the TOOLS tab.
  • Select Trashcan
  • scroll right and open the Operations drop-down menu.
  • Select one option acording to your needs
Warning:
  • Once you permanently delete an object, it cannot be recovered. If an object has parent or child elements and you do not want to delete them as well, do not select the 'Dependencies' option and choose 'Permanently delete'.
  • if you delete a collection that contains objects, the system first deletes the objects; you must then delete the collection. These steps can be reverted separately, as explained in 'Revert deletions'.

Step 7: Upload Data

For the Data Store, it is recommended to attach data to experimental steps that describe how it was generated. In openBIS, data is uploaded as openBIS Datasets. openBIS is agnostic, this means, data can be of any type and format. Small files (up to several Gigabyte) can be uploaded via the web user interface. If you are uploading large data files (on the Terabyte range), please contact the Data Store team first to ensure that the data upload is performed incrementally using a script and the Data Store performance remains stable.

Instructions for uploading data from a zip file.
  1. In the left-hand menu, navigate to the Experimental Step for which you want to upload data [Experimental Step name='Parameter 1']
  2. Select Experimental Step [Name='Macrostructure Characterization']
  3. Click on +Dataset tab
  4. Select Data set Type ='Raw Data'
  5. Enter [Dataset name='Parameter 1 raw']
  6. Enter Comments= 'Synthetic example images for demo purpose'
  7. Select files to upload
  8. Select zip file ('Parameter1_Marcoscopic.zip') and wait that green bar is displayed, indicating upload completion
  9. Select Uncompress before import when uploading a Zip file
  10. Review entries and Save
Warning: The Data Store is a central storage for data, metadata, and their connections. As with any other software, openBIS can not open data in all formats. To work with the data uploaded to the Data Store, download it from the Data Store and upload the next version. If you are working with a version control system such as GitHub, upload the raw data to the Data Store and create experimental steps to document additional steps where the datasets change. For example, data processing or data analysis. You can insert the link(s) to the relevant GitHub repository in the “Comment Log” field or any other field in the respective experimental step, just make sure to use a consistent approach within your division. This makes it easier to find information.

Confirm data upload: In the left-hand menu, navigate to the collection ('Parameter1') and open the experimental step ('Macrostructure Characterization') to which the data was uploaded

CONGRATULATIONS!!, You have uploaded data from a zip file to your experimental step 'Macrostructure Characterization' located in the collection 'Parameter 1'.
